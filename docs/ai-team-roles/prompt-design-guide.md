# Prompt 設計指南

## 概述

本指南旨在協助團隊成員設計有效的 AI prompt，以最大化 AI 助手在專案開發過程中的貢獻。

## 基本原則

### 1. 角色明確性
- 使用 `role: [AI|PM|SA|UX|FE|BE]` 指定 AI 的角色
- 確保每個角色都有清楚的責任範圍
- 保持角色間的一致性和互補性

### 2. 語言要求
- 所有溝通都使用**繁體中文**
- 保持專業術語的一致性
- 使用清晰、簡潔的表達方式

### 3. 內容結構
- 使用結構化的格式來組織 prompt
- 包含具體的任務描述
- 提供必要的背景資訊

## Prompt 設計模板

### 基本模板
```
role: [指定角色]

## 任務描述
[具體說明需要完成的任務]

## 背景資訊
[提供相關的專案背景和限制條件]

## 期望產出
[說明期望的交付成果格式和內容]

## 特殊要求
[任何特殊的技術要求或限制]
```

### 文件產生專用模板
```
role: AI

## 文件類型
[說明要產生的文件類型：技術文件、使用者指南、API 文件等]

## 目標受眾
[明確指定文件的目標讀者]

## 內容範圍
[定義文件應包含的內容範圍]

## 格式要求
- 使用 Markdown 格式
- 包含適當的標題層次
- 提供程式碼範例（如適用）
- 包含圖表或流程圖（如需要）

## 品質標準
- 資訊準確且最新
- 結構清晰易懂
- 包含實用的範例
- 提供後續維護指引
```

## 各角色專用指南

### AI 角色
- 專注於協調和資訊整合
- 提供技術支援和工具使用指導
- 協助產生和維護文件
- 促進團隊溝通

### PM 角色
- 關注商業價值和可行性
- 提供專案規劃和時程安排
- 協助需求分析和優先順序排定
- 風險評估和緩解策略

### SA 角色
- 專注於系統架構設計
- 提供技術選型建議
- 協助設計系統流程和資料結構
- 非功能性需求分析

### UX 角色
- 關注使用者體驗設計
- 提供介面設計建議
- 協助使用者流程設計
- 可用性測試和改善建議

### FE 角色
- 專注於前端實作
- 提供效能優化建議
- 協助元件設計和重用
- 前端技術選型

### BE 角色
- 專注於後端邏輯
- 提供 API 設計建議
- 協助資料庫設計
- 安全性和擴展性考量

## 最佳實踐

### 1. 逐步細化
- 從高層次需求開始
- 逐步細化到具體實作細節
- 在每個階段都要求明確的產出

### 2. 迭代改善
- 根據產出結果調整 prompt
- 記錄有效的 prompt 模式
- 建立團隊的 prompt 資料庫

### 3. 上下文管理
- 提供足夠的背景資訊
- 引用相關的專案文件
- 保持對話的連貫性

### 4. 品質控制
- 設定明確的驗收標準
- 要求提供可驗證的產出
- 建立回饋和改善機制

## 範例應用

### 需求分析範例
```
role: PM

請協助分析以下需求並制定實作計畫：

## 需求描述
建立 AI Team Role Prompt Library 的文件管理系統

## 背景資訊
- 專案使用 Vite + React
- 目前沒有文件管理系統
- 需要支援自動化文件產生

## 期望產出
1. 功能需求清單
2. 技術可行性評估
3. 實作時程規劃
4. 風險評估和緩解策略
```

### 技術設計範例
```
role: SA

請設計自動化文件產生的系統架構：

## 系統需求
- 支援多種文件格式
- 能夠整合 Git workflow
- 支援範本系統

## 技術限制
- 必須與現有 Vite 專案整合
- 偏好使用 Node.js 生態系統
- 需要考慮 CI/CD 整合

## 期望產出
1. 系統架構圖
2. 元件設計說明
3. 資料流程圖
4. 技術選型建議
```

## 注意事項

1. **避免過於複雜的 prompt**：保持簡潔明瞭
2. **提供具體範例**：幫助 AI 理解期望的格式
3. **設定明確界限**：說明什麼不應該包含在產出中
4. **定期更新**：根據使用經驗調整 prompt 設計
5. **文件化記錄**：保存有效的 prompt 模式供團隊重用
